# Shared workflow fixes - 17 October 2026

This change corrects the five findings in the [follow-up review](2026-10-17-followup-leftout-review.md), including neighbouring flows that share the same date, dependency and keyboard rules. Existing Krama colours and page layouts are retained. There are no new dependencies or database migrations.

| Shared rule | Changes |
| --- | --- |
| Workspace changes commit only after accepted navigation | A workspace switch carries its intended destination into a fresh, validated session bootstrap. The active API header, UI state, cache and stored choice remain in the original workspace if the browser's unsaved-work warning is cancelled. Accepted navigation starts at the selected workspace's dashboard and retains the old document draft under its original account/workspace key. |
| Daily data expires at the day boundary | Dashboard and Inbox use the existing shared local-day subscription, including midnight and wake/focus refresh. Do today resolves the server's reporting day immediately before its write. Daily planning also checks the current reporting day and refuses stale-day priority/review writes while refreshing the dashboard. Failed lookups retain the item and do not submit a stale date. |
| Primary content survives related-service failures | Goals and its drawer retain their own usable content when related projects/habits fail. Project details no longer depend on a healthy navigation-list query. If tasks fail, documents, settings and project editing remain available, while task-dependent sections disclose the failure and counts show unavailable. Brain retains note editing when project choices fail. Retry actions target unavailable feeds. |
| Unknown link data is not an unlink instruction | Unavailable link controls are disabled. A Goal form remembers whether each relationship list was available when its draft opened; late recovery cannot turn an initially empty selection into bulk unlink requests. The user can reopen the form after recovery to edit those links. |
| Keyboard events have one owner | App navigation chords claim their prefixes before page-specific handlers. Page commands ignore typing, modifiers, composition, already-handled keys and open modal dialogs. Escape reaches menus/dialogs before the app toggles focus mode. Prefix expiry updates the event handler immediately as well as the visible UI. Conflicting project E-edit advertising was removed; project editing remains available through its existing button. |

## Regression coverage

`e2e/live/shared-workflow-live.spec.ts` adds three cases using real API records in the disposable test workspace: cancelled and accepted switches with a recovered save, a Brain move followed by a real database-backed edit, and usable Goal/project editing during a controlled related-list outage.

The initial wider run exposed an Escape-order regression from this change. The run was stopped; the event priority was corrected; all five targeted menu/chord checks passed; and the frontend was rebuilt before restarting the complete final run. An earlier prefix-expiry check also exposed an event/render timing gap and passed after the handler used the current prefix directly. Assertions were retained rather than weakened. An existing priorities test also needed to wait for save acknowledgement before checking persisted state: a disabled picker can mean a save is still pending, not only that its three-item limit has been reached. Its count, reload and Focus-selection assertions remain intact. A live capture test likewise navigated away before Do today completed; it now waits for the Inbox item to be filed before loading Dashboard, matching the existing complete personal-journey test. Its persistence and validation assertions remain intact.
