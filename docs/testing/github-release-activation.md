It includes earlier requested application/UI repairs as well as the release work; it is a complete source snapshot, not just this turn's small patch. 2. After publication approval, prepare an isolated branch `release/verified-workspace`, preserving the user's current checkout/index. Reconcile it with current remote `main`; review any conflicts or unrelated remote changes. Publish a pull request. Do not force-push, overwrite main, or silently publish excluded local settings.
3. After credential-sharing approval, create the GitHub `ai-verification` environment. Set its non-secret `GEMINI_TEXT_MODEL` variable to `gemini-3.6-flash`. No local database URL, personal JWT/session secret, R2 key or user data belongs in CI. Local credentials have not been uploaded by this preparation.
4. Run the normal pull-request checks, review the published diff, and merge only the approved revision after successful CI. Dispatch `KRAMA release checks` on that exact `main` revision with `real_ai=true`. Verify both provider matrix entries, staging, core and the final gate succeed.
5. Run `corepack pnpm release:github --sha <reviewed-main-sha>` as a read-only preflight. Then, only after activation approval, run the same command with `--apply`. The command refuses a changed main revision, unpublished/different workflow, unconfigured selected model, skipped/failed AI jobs, an untrusted check or conflicting existing branch protection. A final main/protection recheck precedes the single protection write.
